Documentation

Everything you need to set up, configure, and run Tivoria for your salon business.

Introduction

Tivoria is a WhatsApp-first booking platform for Indian service businesses. Customers book appointments by texting your WhatsApp number. You manage everything via WhatsApp commands or a web dashboard.

💡
No app downloads required. Your customers use WhatsApp — which they already have. You manage via WhatsApp + web dashboard.

Architecture

  • Backend: Python / FastAPI / PostgreSQL / Redis
  • Messaging: WhatsApp Cloud API (Meta)
  • Payments: Razorpay
  • Background: Celery (reminders, feedback)
  • Dashboard: Single-page HTML app at /dashboard/

Quickstart

Get running locally in 5 minutes.

Clone & install

# Clone
git clone https://github.com/Nikhil0307/saloon-bookbot.git
cd saloon-bookbot

# Create venv & install
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

Start PostgreSQL & Redis

# Using Docker
docker-compose up -d db redis

# Or use existing instances
# Edit .env with your connection strings

Configure environment

cp .env.example .env
# Edit .env — defaults work for local dev

Run migrations & start

alembic upgrade head
uvicorn app.main:app --reload --port 8000

Seed demo data & open dashboard

curl -X POST http://localhost:8000/dev/seed
# Open http://localhost:8000/dashboard/
# Login: 9999900000 + any 6-digit OTP

WhatsApp Setup

Connect your WhatsApp Business number to Tivoria.

Create Meta Business Account

Go to business.facebook.com and create or use existing business account.

Meta Business Suite
Navigate to business.facebook.com → Settings → Business Info
Note your Business ID for later use

Enable WhatsApp Cloud API

In Meta Developer Portal, create an app and add WhatsApp product.

developers.facebook.com
My Apps → Create App → App Name & Contact Email → Use Case: Connect with customers through WhatsApp → Business Portfolio → Overview → Create App
Left menu: Use cases → Connect with customers through WhatsApp → Customize → API Setup (Phone Number ID) & Configuration (Webhook)

Configure Webhook

Point Meta to your Tivoria server.

# In Meta Dashboard → WhatsApp → Configuration

Callback URL:   https://yourdomain.com/webhooks/whatsapp
Verify Token:   your-verify-token   # matches META_WEBHOOK_VERIFY_TOKEN in .env

# Subscribe to:
messages        ✓

Update .env

META_APP_ID=your-app-id
META_APP_SECRET=your-app-secret-or-access-token
META_WEBHOOK_VERIFY_TOKEN=your-verify-token

Link tenant to phone number

In dashboard, the tenant's waba_phone_number_id must match your WhatsApp Phone Number ID.

# Via SQL or dashboard settings
UPDATE tenants
SET waba_phone_number_id = 'your-phone-number-id'
WHERE owner_phone = '+919999900000';

Managing Services

Services can be standalone or organized in parent/child hierarchy.

Service Hierarchy

Create categories (parent services) to group related services:

# Parent category (not bookable)
{ "name": "Hair Services", "duration_minutes": 0 }

# Child service (bookable)
{ "name": "Haircut", "duration_minutes": 30, "price_paise": 50000, "parent_service_id": "<category-id>" }

# Standalone service (no parent, bookable)
{ "name": "Facial", "duration_minutes": 60, "price_paise": 150000 }

Service Fields

API Reference

All endpoints under /api. Authenticated via JWT Bearer token.

Authentication

POST /api/auth/login Get JWT token

Request

{ "phone": "+919999900000", "otp": "123456" }

Response

{
  "access_token": "eyJhbG...",
  "token_type": "bearer",
  "tenant_id": "uuid",
  "business_name": "Style Studio"
}

Usage

# Include in all subsequent requests
Authorization: Bearer <access_token>

Services API

GET/api/servicesList all (tree)

Returns flat list with children array on parent items.

POST/api/servicesCreate service
{ "name": "Haircut", "duration_minutes": 30, "price_paise": 50000 }
PUT/api/services/{id}Update service

Send only fields to update. Supports is_active, sort_order, etc.

DELETE/api/services/{id}Soft delete

Sets is_active = false.

Staff API

GET/api/staffList active staff

Returns array of staff with skills, working_hours.

POST/api/staffAdd staff
{ "name": "Meena", "role": "stylist", "skills": ["svc-uuid-1", "svc-uuid-2"] }
PUT/api/staff/{id}Update staff

Partial update. Supports is_active, working_hours, skills.

DELETE/api/staff/{id}Soft delete

Sets is_active = false.

Bookings API

GET/api/bookingsList with filters

Params: from_date, to_date, status (comma-separated), staff_id, customer_id, page, per_page.

# Example
GET /api/bookings?status=confirmed,pending_deposit&from_date=2026-05-27&page=1&per_page=20
GET/api/bookings/{id}Booking detail

Returns full booking with customer, service, staff names.

PUT/api/bookings/{id}/statusChange status
{ "status": "completed" }  // or cancelled, no_show

Customers API

GET/api/customersList + search

Params: search (name/phone), page, per_page.

GET/api/customers/{id}Detail + booking history

Returns customer profile with recent bookings and feedback.

Analytics API

GET/api/analytics/overviewDashboard overview

Today's bookings, week revenue, total customers, popular services, ratings.

GET/api/analytics/bookingsBooking trends

Params: from_date, to_date. Returns daily counts by status.

GET/api/analytics/revenueRevenue breakdown

Revenue by service, by day. Params: from_date, to_date.

GET/api/analytics/staffStaff utilization

Bookings per staff, completion rate, revenue. Params: from_date, to_date.

Docker Deployment

BASH# Production
cp .env.prod.example .env.prod
# Edit .env.prod with real credentials

docker-compose -f docker-compose.prod.yml up -d

This starts: PostgreSQL, Redis, app (Gunicorn + Uvicorn workers), Celery worker, Celery beat, Nginx.
